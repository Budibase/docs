This tutorial will take less than 5 minutes, and at the end, you will have successfully built a complete CRUD application.

We will use the [Sample data](https://docs.budibase.com/docs/data-sources#sample-data), which includes a few tables with various data types to look at.

***

## Getting started

1. Create a new account at [https://account.budibase.app/register](https://account.budibase.app/register) (onboarding takes a few seconds). 
2. Once registered, you will be able to login. 
3. Step through the first app wizard, selecting the *Budibase Sample data*.

## Data

Most of the columns, for example *First Name*, *Last Name* and *Email*, are [Text](doc:text) data types, which is the most common.

Other types include [Number](doc:number), [Date/Time](doc:datetime), and more!

The values of some fields are highlighted in a grey pill. This indicates the value to be either a [Multi-select](doc:multi-select) value such as the *Employee Level* in the **Employees** table, or a [Relationships](doc:relationships) link such as *Assigned* in the **Jobs** table.

## Design

As we have some data, we can now start building out the front-end of our app. This is done in the Design section, which can be navigated to via the tab at the top of the page. 

<Image alt="Navigating to the Design section" align="center" src="https://files.readme.io/3077df5-Screenshot_2023-02-17_at_17.56.01.png">
  Navigating to the Design section
</Image>

The left hand panel includes four core areas for building out your apps:

1. [Screens](doc:screens)
2. [Components](doc:components)
3. [Theme](doc:app-theming)
4. [Navigation](doc:navigation)

When building apps you will mostly be focused on the *Screen* and *Component* views. 

<Image alt="The core areas of the Design section" align="center" src="https://files.readme.io/f198c7b-left_panel.gif">
  The core areas of the Design section
</Image>

### Autogenerated screens

To get started quickly, click on `Add screen`. Next select `Autogenerated screens` to create new CRUD (Create, Read, Update, Delete) screens for each of your tables.

These autogenerated CRUD screens will make use of the [Table block](doc:table-block) and [Side panels](doc:side-panel) for fast, all-in-one data interaction. 

<Image alt="Adding autogenerated screens" align="center" src="https://files.readme.io/e8573b6-Screenshot_2023-02-17_at_18.09.27.png">
  Adding autogenerated screens
</Image>

<Image alt="Creating an auto screen for each table" align="center" src="https://files.readme.io/89dc3ca-Screenshot_2023-02-17_at_18.09.40.png">
  Creating an auto screen for each table
</Image>

When creating screens you will be asked to provide an access level, but this can always be changed later. 

You can read more about [screen access levels](https://docs.budibase.com/docs/screens#access-level), but in this tutorial we will stick to the default of *Basic* access.

<Image alt="Selecting new screen access level" align="center" src="https://files.readme.io/3d3e656-Screenshot_2023-02-17_at_18.14.34.png">
  Selecting new screen access level
</Image>

Upon click `Done` a new screen will be generated for each table selected.

<Image alt="Autogenerated screens" align="center" src="https://files.readme.io/4b5af70-Screenshot_2023-02-17_at_18.15.50.png">
  Autogenerated screens
</Image>

### Components

With the screens created we can view and edit the components for each. An easy way to navigate to the components panel is to click on the table within the design view.

<Image alt="Hovering the mouse over the table block" align="center" src="https://files.readme.io/8e226c9-Screenshot_2023-02-17_at_18.32.16.png">
  Hovering the mouse over the table block
</Image>

<Image alt="Clicking on the table block to quickly navigate to the components panel" align="center" src="https://files.readme.io/f695b93-Screenshot_2023-02-17_at_18.33.03.png">
  Clicking on the table block to quickly navigate to the components panel
</Image>

With the table block selected, you will be able to edit its settings via the <Glossary>Settings Panel</Glossary>. Here you can change the *Title*, *Data*, *Configure columns*, *Sorting*, *Filtering*, and more! These settings are explained on the [Table block](doc:table-block) page.

You can also click `Add component` to add another component to your screen. You can view a list of available core [Components](doc:components) and learn more about [Data in design](doc:working-with-data).

### Blocks

In Budibase there is a category of components known as [Blocks](doc:blocks), which are collections of pre-built components designed to make building your apps easier and faster.

A list of them can be found in the *Blocks* tab of the components view. 

<Image alt="Available Budibase blocks" align="center" src="https://files.readme.io/0269988-Screenshot_2023-02-17_at_18.51.21.png">
  Available Budibase blocks
</Image>

Sometimes you will find yourself needing to make a fine-grain tweak that cannot be done through the settings panel alone. 

If you wanted to edit the form fields in the side panel of a Table block, for example, you will need to click the [Eject](https://docs.budibase.com/docs/blocks#ejecting-blocks) button to pop open the block. 

<Image alt="Ejected table block resulting in a detailed component tree" align="center" src="https://files.readme.io/be40ab6-Screenshot_2023-02-17_at_18.59.00.png">
  Ejected table block resulting in a detailed component tree
</Image>

## Preview and Publish

During development you may wish to test out your app so far. Click the `Preview` button in the top-right to open the app in a new browser tab. The app will always open the [Home screen](https://docs.budibase.com/docs/screens#home-screen). 

<Image alt="Preview and Publish buttons" align="center" src="https://files.readme.io/0cbb74c-Screenshot_2023-02-17_at_19.03.35.png">
  Preview and Publish buttons
</Image>

<Image alt="App preview showing a 'Detail' side panel" align="center" src="https://files.readme.io/2f6ef5e-Screenshot_2023-02-17_at_19.06.41.png">
  App preview showing a 'Detail' side panel
</Image>

You will also notice that navigation links were automatically added to the nav bar when we created the autogenerated screens.

To view the app with a different permission level, toggle the `View as basic user` option. 

<Image alt="A public user does not have permission to view the app by default" align="center" src="https://files.readme.io/b28c7b3-Screenshot_2023-02-17_at_19.09.48.png">
  A public user does not have permission to view the app by default
</Image>

When you are happy with your app, click `Publish` to make your app live in production. 

<Image alt="Publishing an app" align="center" src="https://files.readme.io/4781b5d-Screenshot_2023-02-17_at_19.12.05.png">
  Publishing an app
</Image>

<Image alt="App published!" align="center" src="https://files.readme.io/650fece-Screenshot_2023-02-17_at_19.15.07.png">
  App published!
</Image>

When your app is published, you will have the choice of clicking `Done` which will close the modal and keep you in the **Design** section, or you can `View App` on the public URL.
